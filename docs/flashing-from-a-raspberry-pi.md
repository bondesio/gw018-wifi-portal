# Flashing a GW018-DM from a Raspberry Pi

We flashed the gateway with a Raspberry Pi using its GPIO UART directly. This
procedure writes the WBRG1 (RTL8721CSM) network processor; it does not flash
the separate ZS3L Zigbee processor. Back up the original flash first and use
only the images built for this project.

## Hardware and wiring

You need a Raspberry Pi with its hardware UART enabled, access to the GW018-DM
P1 UART pads/header, and the three WBRG1 build images. Opening the case and
soldering header pins may be required.

Connect the Pi's 40-pin header UART to the gateway with TX/RX crossed:

| Raspberry Pi | GW018-DM P1 |
| --- | --- |
| GPIO14 / TXD, physical pin 8 | RX |
| GPIO15 / RXD, physical pin 10 | TX |
| GND, e.g. physical pin 6 | GND |
| 3.3 V or 5 V | Leave unconnected |

The Pi UART uses 3.3 V logic. Power the gateway normally over USB-C; never
power it from the Pi. Confirm the P1 pinout on your exact board revision
before wiring, since a mistake can damage either device.

## Pi serial setup and tools

Disable the serial login console and enable the hardware serial port (for
Raspberry Pi OS, use `sudo raspi-config` → Interface Options → Serial Port;
answer “No” to the login shell and “Yes” to the serial hardware). Reboot if
the setting changed, then verify that `/dev/serial0` exists. The Pi's UART
must support 921600 baud.

The required flasher is the Realtek/AmebaD ImageTool CLI, `upload_image_tool_linux`,
and its `imgtool_flashloader_amebad.bin` support file. Obtain them separately
from the [AmebaD Arduino tools](https://github.com/Ameba-AIoT/ameba-arduino-d/tree/master/Arduino_package/ameba_d_tools_linux)
and review their upstream terms. They are not redistributed here. The three
firmware images are `km0_boot_all.bin`, `km4_boot_all.bin`, and
`km0_km4_image2.bin`, generated by following the build instructions in the
repository README.

Build the firmware on a supported x86-64 Linux computer if needed, then copy
the three images to the Pi. The prebuilt Linux ImageTool available from the
vendor may be x86-64 and will not run natively on an ARM Pi. Check the binary
and Pi architecture:

```sh
file ./upload_image_tool_linux
uname -m
```

Use an ARM-compatible build of the uploader for the Pi. This repository does
not include or validate a Pi-native ImageTool binary. The uploader must also
support the Pi UART device and the download-mode/reset sequence needed by the
GW018-DM; simply changing a USB serial path to `/dev/serial0` is not
necessarily sufficient. If you do not have a compatible Pi build, use the
documented x86-64 Linux host procedure in the main README instead.

## Flash

Stage the ImageTool, `imgtool_flashloader_amebad.bin`, and the three firmware
images together in one directory on the Pi. Power the gateway over USB-C and
use the uploader's supported boot/download-mode sequence. From that directory,
run the upstream RTL8721CSM erase and write commands, using `/dev/serial0`:

```sh
chmod +x ./upload_image_tool_linux

# Erase/prepare the target
./upload_image_tool_linux "$PWD" /dev/serial0 ameba_rtl8721csm Enable Enable 921600

# Write the KM0 and KM4 firmware images
./upload_image_tool_linux "$PWD" /dev/serial0 ameba_rtl8721csm Enable Disable 921600
```

Wait for successful completion before removing power. Reboot and verify that
the gateway starts normally. Do not interrupt power during erase or write.
`OTA_All.bin` is for later WBRG1 OTA updates; it is not one of the three files
used for this first UART flash. Never use this procedure to write firmware to
the ZS3L Zigbee processor.
